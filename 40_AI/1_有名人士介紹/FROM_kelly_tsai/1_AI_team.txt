	三個等級，差別在AI之間到底要不要說話
		1. subagent : 各自回報
			* 次agent 彼此之間不溝通模式
			* 各自負責各自的工作
			* 適合界定很清楚又能同時做的事情
				- 一次幫一堆檔案各寫測試
				- 同時爬好幾個網站
		2. agent teams : 進群對齊
			* AI 之間有一個內建的群組聊天室
			* 各自負責各自的工作，但可以互相傳訊息共用一張代辦清單，自己去認領任務
				類似三個人同時進入會議室，邊做邊更新白板
				一個人有新的發現其他人也會馬上知道
			* 適合任務彼此有交叉，一個人的方向會影響另一個人下一步的工作
		3. dynamic workflows : 只需要告知最終目標(目標其他都不用管)
			* 連團隊都不用自己組
			* 僅需要管理好你的目標
			* AI實作方(claude、chatgpt)自己寫一份分工計畫
			* 動態一口氣開出幾百個分身平行跑
			* 做完他會自己驗收，最後才把結果交給你
			* 它能開這麼多又不卡，因為那份計畫存在程式的變數裡面，不會一直佔著
				AI實作方(claude)的腦容量
			=> 主打超大規模可完全拆開來做的任務


	組AI團隊常見誤區
		* 直覺按角色來拆分
			* 一個agent去規劃
			* 一個agent來寫
			看起來很有條理但其實這樣最容易出事
			因為工作在agent之間交接時，資訊會一直掉
				=> 最後就會變成一個傳話遊戲
			=> 比較穩的是按 context 來拆，照誰需要看到哪一些資料來分，而非照頭銜

		* 多 agent 真的有比較強嗎?
			多個AI一起做常常其實沒有比一個強
			// 研究論文:算力給的一樣多的時候 ，單一AI贏過多agent
				過去那些多agnet比較強的其實是偷偷給了多agent多很多算力
				一旦把思考的份量拉到一樣時，單一AI在很多要一步步推理的任務上反而打平
		* 任務種類處理效率
			* 可以拆開平行做的事
				比如看同一家公司的營收成本市場，多agent確實可以加速，研究裡這類可以進步八成
			* 但要是一件事情得一步接一步有先後，那多agent反而卡(google研究發現多agnet都會退步，最多退到七成)
				比如寫code，多半共用同一套上下文，於標準的程式測試上，單一AI常常還比較強
					結構好的可以幫你加速，結構亂的會把錯誤率放大17倍以上
				=> 同樣的技術結果差這麼多，全看你會不會設計

			研究顯示多agent在實際生產環境失敗率常常過半，問題出在系統設計而不在模型本身
				=>最常見錯誤就是滾雪球
					前面的agent出一點點小錯，後面agent接續，會越來越歪
		* 錢的問題
			有人統計3個agent花的錢可能是1個agent的10倍
				* 因為每叫一個agent的設定、能用的工具每叫一次都要重算一次錢
				* agent之間每傳一次話也要錢
				* agent一多彼此要連的線就暴增: 五個 agent 就有 10 條線
				* 再加上做到一半如果出錯重跑，它會把前面的診斷對話再帶一遍，越到後面越燒錢，因為ai是用量計費的
				* 所以一群一起燒帳單一定長得更快

		但若碰對任務的話就真的很強
			如一開頭講的75萬行11天將專案翻寫完，規模夠大拆的開又現成的測試可以驗收

		真正值錢的不是會開一堆agent，而是判斷出來什麼時候應該要開團隊，什麼時候用一個就夠了
			會開不稀奇，知道什麼時候該開才是重要的

	你也能開一支AI團隊
		以使用 replit 為例
			針對沒有寫程式的人說算好上手
			* 平行作業能力
			* 不同agent協作能力
